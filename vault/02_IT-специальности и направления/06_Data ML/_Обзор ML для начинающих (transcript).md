# Обзор ML для начинающих — transcript

Транскрипт обзорного русскоязычного видео по машинному обучению. Без кода, почти без формул. Полезен как опорный конспект «как смотреть на задачи глазами Data Scientist-а» и какие проблемы ждут на проектах.

## TL;DR

- ML решает задачи, для которых сложно прописать алгоритм: оценка недвижимости, спам, диагнозы, картинки/звук/речь. Ключ к успеху — данные.
- Базовые модели: линейная регрессия (коэффициенты по признакам), дерево решений (рекурсивное разбиение), нейросеть (матрицы коэффициентов между слоями признаков).
- Типы задач: с учителем (регрессия, классификация), без учителя (кластеризация, аномалии), с подкреплением (игры, биржа, робототехника). По данным: Classic ML на табличках, Deep Learning на тексте/звуке/изображениях (CV, NLP).
- Этапы проекта: нужна ли в принципе ML → загрузка (SQL) → разведочный анализ → очистка/выбор признаков → обучение и валидация → сохранение модели и деплой через сервис (FastAPI/Django/Flask).
- Главные проблемы: некачественные данные, смещенная выборка, переобучение (сложная модель, мало данных → регуляризация или проще модель), недообучение, дата дрифт, бесконтрольное поведение модели на краевых случаях.
- Совет по обучению: для работы — Classic ML первым, потом ниши. Математика нужна на уровне понимания моделей, не на уровне вывода формул. Книга — Жерон «Практическое машинное обучение».

## Что такое ML

Компьютеры изначально для автоматизации рутины. Но автоматизация ≠ сложность. Посчитать рулоны обоев или симуляцию жидкости — есть четкий алгоритм. А оценить квартиру, одобрить кредит, поймать спам, отличить птицу от самолета, определить эмоциональную окраску — алгоритм прописать не выходит, потому что слишком много исключений.

ML решает именно такие задачи. Его ключ — данные:

- у банков — тысячи сделок с недвижимостью;
- о мошенничестве и спаме клиенты сообщают сами;
- пользователи соцсетей подписывают свои фото.

DDD (Data-Driven Decision) — отдельная концепция, ей занимаются дата/бизнес аналитики. ML идет дальше: если данных о решениях задачи достаточно, можно обучить модель, которая заменит алгоритм.

ML-модель — функция с параметрами. Обучение = автоматический подбор параметров так, чтобы на известных данных отклонение от правильных решений было минимальным.

## Основные модели

### Линейная регрессия

Каждый признак умножается на свой коэффициент, всё суммируется. Коэффициенты считаются по готовой формуле — подставляешь матрицу данных и значений целевой переменной.

- Знак коэффициента = направление влияния, модуль = важность признака.
- Пример: для квартиры коэффициент при площади — большой положительный, при расстоянии до центра — отрицательный, при этажности — близко к нулю.

### Дерево решений

Рекурсивно разбивает данные на две части так, чтобы в каждой объекты были похожи по целевой переменной. На каждом шаге пробуются все возможные разбиения, выбирается лучшее. Когда разбивать дальше нет смысла — каждая группа заменяется средним значением.

Предсказание для нового объекта: спускаемся по дереву до листа.

### Нейронная сеть

Похожа на линейную регрессию, но коэффициенты — это матрицы. Они отображают признаки не сразу в ответ, а в промежуточные признаки (как промежуточные вычисления в задачах по физике). Операция = «слой», слоев может быть много.

Что за промежуточные признаки — мы не знаем и не контролируем, сеть определяет это сама. Из-за большого числа параметров нейросети умеют сложные зависимости: речь, звук, изображения.

## Типы задач

По наличию разметки:

| тип | что есть | примеры |
|---|---|---|
| с учителем | данные + разметка | регрессия (стоимость, температура), классификация бинарная (спам/не спам) и мульти-классовая (диагнозы, животные) |
| без учителя | только данные | кластеризация (сегменты абонентов), детекция аномалий |
| с подкреплением | нет немедленного правильного ответа | игры, биржа, робототехника |

По типу данных:

- **Classic ML** — табличные данные. Линейная регрессия + деревья и их ансамбли.
- **Deep Learning** — текст, звук, изображения. Нейросети.
  - **CV** (Computer Vision) — изображения, видео. Доп. задачи: сегментация, генерация.
  - **NLP** — речь, текст. Доп. задачи: эмоциональная окраска, поиск ответов, генерация.

Генеративные модели (Midjourney, ChatGPT, Stable Diffusion, DeepSeek, Grok, Claude, Gemini) подняли всеобщий интерес к ML.

## Этапы ML-проекта

### 0. Нужен ли ML вообще

ML стоит, только если есть четкая проблема и обычные алгоритмы не справляются. Если простой keyword-классификатор писем ошибается на нескольких в месяц — это не повод тащить NLP. А вот для подозрительных областей на медицинских снимках или для рекомендательной системы — оправдано.

### 1. Загрузка данных

В пет-проектах данные уже в CSV. В реальности — БД или data lake, и достать оттуда чаще всего через **SQL**. Поэтому SQL спрашивают почти во всех DS-вакансиях. На этом этапе если не уверен, нужен ли признак — лучше загрузить.

### 2. Разведочный анализ (EDA)

Простые статистики (mean, min, max, median, std) + гистограммы по непрерывным и столбчатые по категориальным + матрица корреляций.

Что подсветится:

- странные значения (отрицательный возраст, 150 этажей) → проблема загрузки;
- нулевая/маленькая дисперсия → колонка бесполезна;
- перекос гистограмм → знай об этом;
- выбросы;
- линейные зависимости по корреляциям (от −1 до +1).

EDA — почти творческий процесс.

### 3. Очистка данных + выбор признаков

- Слишком редкие значения убрать (банк, 500 клиентов из 100к с докторской — модель не научится).
- Выбросы фильтровать (40-этажка среди сталинок).
- Пропуски: при большом проценте — удалить колонку; иначе удалить строки или заменить средним.
- Признаки: меньше — лучше, чем слишком много (5–40 типично). Старт — небольшой набор самых важных по здравому смыслу или корреляциям.

Изображения уже матрица пикселей. Текст — токенизируется в символы/слова, длинные обрезаются, короткие добивают паддингом.

### 4. Обучение и валидация

- Сплит на train (50–90%) и validation. Случайно.
- Train без valid — как зазубривание билета. Valid нужен, чтобы понять, что модель работает на новых данных.
- Сравнение по метрикам: для регрессии — средний процент отклонения; для классификации — точность.
- Не устраивает метрика → назад: новые признаки или другая модель.

### 5. Деплой

Этим часто занимается **ML инженер** (отдельная роль). Data Scientist сохраняет модель как файл, ML-инженер пишет небольшой backend на **FastAPI / Django / Flask**, который грузит модель и отвечает на HTTP-запросы. Это микросервисная архитектура: к модели обращаются другие сервисы.

## Пример проекта end-to-end

Сайт-агрегатор объявлений недвижимости, нужна метка «Рыночная цена». Допустимая погрешность 10%.

1. SQL-запрос вытаскивает данные за последний год (рынок меняется).
2. EDA находит: материал стен пропущен у 40% — выкидываем; есть 2-этажки и редкие квартиры дороже 500 млн — фильтруем (<1% данных). Корреляции — самые сильные с площадью, числом комнат, расстоянием от центра.
3. Берем эти 3 признака → линейная регрессия → 17% средней ошибки. Многовато.
4. Эксперт-оценщик советует добавить наличие балкона и состояние ремонта (0/1) → 12%.
5. Градиентный бустинг (на деревьях) → 7%. Сохраняем модель.
6. ML-инженер делает HTTP API — оно дергается при добавлении объявления.

## Типовые проблемы

### Данные

- **Некачественные/отсутствующие данные** — после очистки выборка непригодна для обучения.
- **Отсутствие сигнала** — никакие признаки не коррелируют с результатом в достаточной степени. Пример: предсказание цены акций только по истории цен — невозможно без учета политических и экономических событий.
- **Смещенная выборка** — данные плохо отражают реальность. Распознавание лиц хуже работает с цветными людьми; рекомендательная система игнорирует новых пользователей. Самое опасное: проблема не помешает обучить модель, метрики наоборот могут вырасти.

### Обучение

- **Переобучение** — сложная модель + мало данных. Модель запоминает ответы вместо зависимостей. Train-ошибка ≈ 0, valid-ошибка огромная. Решения: больше данных, проще модель, регуляризация (например, ограничение глубины дерева).
- **Недообучение** — слишком простая модель для сложной задачи. Большие ошибки и на train, и на valid. Решение — модель посложнее.

### В продакшене

- **Дата дрифт** — зависимости в данных меняются. Пример: льготная ипотека резко увеличила стоимость жилья → старая модель занижает; спаммеры смешивают латиницу с кириллицей. Решения: периодически переобучать, мониторить метрики моделей в реал-тайме.
- **Поведение на краевых случаях** — у ML нет гарантий, в отличие от классических алгоритмов. Влиять можно только через данные. Даже точная модель может выдавать отрицательную стоимость. Это риск ML по умолчанию.

## С чего начинать

- Для себя — можно сразу нейросети и CV, ради интереса.
- Для работы — **сначала Classic ML**. Большинство вакансий именно по нему, и даже в других специализациях на интервью спросят Classic ML. Это не унылая область — много интересных моделей, развивает чутье.
- Книга — Жерон, «Практическое машинное обучение».
- Математика: разработчики библиотек спрятали ее за абстракциями. Глубоко знать не нужно — достаточно базовых концепций моделей чуть глубже обзорного видео. Это нужно не для интервью, а чтобы понимать причины проблем и не делать глупых шагов. Пример: новый элитный ЖК с ценами выше максимума в обучающей выборке — дерево решений не справится, линейная регрессия справится.
