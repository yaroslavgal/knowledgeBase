## Модели данных — разделение

### ❌ Антипаттерн: все модели в `domain`

```go
package domain

type User struct {  // одна модель для всего
    ID        int       `db:"id" json:"id"`
    Name      string    `db:"name" json:"name"`
    PasswordHash string `db:"password_hash" json:"-"`
    CreatedAt time.Time `db:"created_at" json:"created_at"`
}
```

**Проблема:** db-теги в domain-модели = слой репозитория просочился в бизнес-логику. JSON-теги тоже не место в domain.

### ✅ Правильно: 3 разные модели + конвертеры

```go
// domain/user.go — бизнес-сущность
package domain

type User struct {
    id        int
    name      string
    password  string  // приватные поля!
    createdAt time.Time
}

func New(name, password string) (*User, error) {
    if name == "" { return nil, ErrEmptyName }
    if len(password) < 8 { return nil, ErrShortPassword }
    return &User{name: name, password: password}, nil
}

// repository/user_db.go — модель для БД
package repository

type UserDB struct {
    ID        int       `db:"id"`
    Name      string    `db:"name"`
    Password  string    `db:"password_hash"`
    CreatedAt time.Time `db:"created_at"`
}

func (u *UserDB) ToDomain() *domain.User { /* конвертер */ }

// transport/user_dto.go — модель для API
package transport

type UserDTO struct {
    ID        int       `json:"id"`
    Name      string    `json:"name"`
    CreatedAt time.Time `json:"created_at"`
    // password НЕ возвращаем!
}

func FromDomain(u *domain.User) *UserDTO { /* конвертер */ }
```
