## Data Race — скрытый убийца

`counter++` — НЕ атомарная операция. Это три шага: чтение → инкремент → запись. Две горутины могут прочитать одно значение, обе прибавить 1, обе записать одно и то же — потеря инкремента.

```go
// БАГ — счётчик меньше 1000 случайным образом
var counter int
for i := 0; i < 1000; i++ {
    go func() { counter++ }()
}
```

Коварство: на 3 горутинах баг может не проявиться, на 1000 — проявится. На тестах прошло, в проде стрельнуло.

**Два решения:**

```go
// 1. atomic — для одиночной переменной
var counter atomic.Int64
counter.Add(1)

// 2. Mutex — для группы операций
var mu sync.Mutex
mu.Lock()
counter++
balance -= amount
mu.Unlock()
```

**Detector:** `go run -race main.go` или `go test -race ./...`. Ловит data race, **не race condition** (это разные вещи: data race = одновременный доступ, race condition = неправильный порядок).

⚠️ `-race` даёт overhead 5–10× CPU и 2× память. В проде не включают.

Аналогия: два кассира одновременно смотрят в тетрадку «продано 50», каждый продаёт билет, оба пишут «51». А должно быть 52. Mutex = замок: пока один пишет, другой ждёт.
