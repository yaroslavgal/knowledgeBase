## Утечка горутин — самая коварная боль

Горутины не собираются GC. Зависшая горутина живёт до конца процесса.

### Классическая утечка через канал

```go
// БАГ
func slow() string {
    ch := make(chan string)        // НЕ буферизированный
    go func() { ch <- fetchSlow() }()
    select {
    case s := <-ch:
        return s
    case <-time.After(1 * time.Second):
        return "timeout"
    }
    // если timeout — горутина повисла на ch <- навсегда
}
```

**Фикс:** `make(chan string, 1)` — буфер на 1. Тогда даже если никто не прочитает, горутина не повиснет.

### First-response-win с утечкой

Задача с собеса: запрос к 5 репликам, берём первый ответ.

```go
// БАГ — 4 горутины повиснут
ch := make(chan Result)  // unbuffered
for _, r := range replicas {
    go func() { ch <- query(r) }()
}
return <-ch
```

**Фикс:** `make(chan Result, len(replicas))`. Каждая горутина гарантированно сможет записать, даже если её результат не будет прочитан.

### Как обнаружить в проде

- `pprof goroutine` профиль — растёт? утечка
- Метрика `go_goroutines` — линейный рост = утечка
- Библиотека `goleak` — в тестах
- Всегда передавай `context` для отмены
