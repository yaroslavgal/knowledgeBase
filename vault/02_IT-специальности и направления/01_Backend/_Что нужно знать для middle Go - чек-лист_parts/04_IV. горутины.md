## IV. ГОРУТИНЫ

### Junior
```go
for _, n := range notifications {
    go func() {
        sendNotification(n)  // БАГ #1: замыкание на переменную цикла
    }()
}
// БАГ #2: горутины не отслеживаются — утечка
```

### Middle
```go
func processNotifications(ctx context.Context, notifications []Notification) error {
    g, ctx := errgroup.WithContext(ctx)
    for _, n := range notifications {
        n := n  // локальная копия (Go 1.22+ можно убрать, но паттерн знать)
        g.Go(func() error {
            select {
            case <-ctx.Done():
                return ctx.Err()
            default:
                return sendNotification(ctx, n)
            }
        })
    }
    return g.Wait()
}
```

**Ключи:** `errgroup.WithContext`, копия переменной цикла (`n := n`), `select` с `<-ctx.Done()`, не запускай горутину без понимания, кто её ждёт. Worker pool через каналы. `sync.WaitGroup` для базовых случаев. Знаешь про `context.Background` vs `context.TODO`.

**Замыкание на переменную цикла:** В Go 1.22+ поведение for-loops изменилось — переменная теперь создаётся в каждой итерации. Но на собесе спросят про "старое" поведение, потому что код 1.21- ещё в продакшене.
