## V. ИНТЕРФЕЙСЫ

### Junior
```go
type UserService struct {
    repo *PostgresUserRepository  // жёсткая привязка к Postgres
}
```

### Middle
```go
// Интерфейс ОПРЕДЕЛЯЕТСЯ ТАМ, ГДЕ ИСПОЛЬЗУЕТСЯ
type UserRepository interface {
    FindByID(ctx context.Context, id int) (*User, error)
    Save(ctx context.Context, user *User) error
}

type UserService struct {
    repo   UserRepository
    logger *slog.Logger
}
```

**Принципы Go-интерфейсов:**
- Маленькие (1–2 метода) — `io.Reader`, `io.Writer`
- Определяются в потребителе, не в реализации
- Неявная реализация (если структура имеет нужные методы — она интерфейс)
- Зависишь от абстракции, не от конкретики

**Бонус:** Понимаешь Interface Segregation Principle. Знаешь, что `interface{}` теперь `any`. Не злоупотребляешь интерфейсами там, где нужна обычная структура.
