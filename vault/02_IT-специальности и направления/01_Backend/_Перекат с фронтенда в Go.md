# Перекат с фронтенда в Go

Фронтенд переполнен, Go в дефиците. Это не лозунг — это статистика.

## Зачем перекатываться

Если в продуктовой команде 3 бэкендера и 1 фронтендер — шансы попасть на бэк банально выше.

---

## Кто реально перекатывается

**Реалистичные сроки:** 2–3 месяца если есть фулстек-база, 4–6 месяцев если идёшь с чистого фронта, 6–12 месяцев если параллельно с работой и без базы бэкенда.

Зарплатная разница: +50–100к в среднем при прочих равных. Не «удвоение за месяц», но ощутимо.

---

## Снимаем розовые очки

На бэке не rocket science. 80% задач — те же круды, просто с другой стороны API.

«Очень большая вероятность, что ты будешь заниматься теми же самыми крудами, но только на бэкенде» — Эмиль.

Что реально другое:
- Цена ошибки выше — баг в фронте = разъехавшаяся вёрстка, баг в бэке = потеря данных или утечка
- Тесты обязательны — на фронте можно забить, на бэке нет
- ADR, технические проекты, OpenAPI-спеки — инженерная культура строже
- Мониторинг, structured logging, distributed tracing — без этого прод не существует
- System Design на собесах даже в средних компаниях

---

## Роадмап перехода (3 месяца)

### Месяц 1: Go синтаксис + база бэкенда

- Tour of Go (go.dev/tour) — 3–5 дней, интерактивный мини-курс
- Go by Example (gobyexample.com) — параллельно
- Книга Donovan & Kernighan «Язык программирования Go» — главы 1–8
- Практика: написать CLI-утилиту для своих рабочих задач (парсер, скрипт автоматизации)
- Указатели, структуры, методы, интерфейсы, горутины и каналы — освоить полностью

### Месяц 2: HTTP, БД, инфраструктура

- HTTP-сервер на стандартной библиотеке (net/http)
- PostgreSQL (раньше работал только с REST? Время учить SQL глубже): SELECT/JOIN, транзакции, индексы
- Driver pgx или sqlc — стандарт индустрии
- Redis — кэш, простые операции
- Docker и docker-compose — поднять локально Postgres + Redis + сервис
- Linux: базовые команды, работа с процессами, журнал, ssh

### Месяц 3: Архитектура, очереди, микросервисы

- Слоистая архитектура: handler → service → repository
- gRPC + Protocol Buffers — базовое понимание
- Kafka или RabbitMQ — спрашивают «чуть ли не на джуна», по словам Эмиля
- 1–2 пет-проекта продакшен-уровня (структура, тесты, README, Docker-сборка, CI)
- Аутентификация: JWT, OAuth basics
- Параллельно: подготовка к собесам по типовым вопросам Go-мидла

## Что меняется на собесах

Фронт-собесы → Go-собесы:

| Тема           | Фронт                        | Go-бэк                                    |
| -------------- | ---------------------------- | ----------------------------------------- |
| Конкурентность | Event loop, async/await      | Горутины, каналы, sync, race conditions   |
| Базы данных    | REST + почти ничего          | SQL глубоко, индексы, транзакции, EXPLAIN |
| Архитектура    | Компоненты, state management | Микросервисы, очереди, кэши, шаблоны      |
| System Design  | Только в Яндекс/Тинькофф     | Везде с уровня middle                     |

Готовиться к Go-собесам — отдельный проект на 3–4 недели после освоения языка. Mock-собесы критичны.

---

## AI и страх замены

Бежать от AI в Go бесполезно. AI заменяет джуновскую работу одинаково — что фронт, что бэк.

«Написать пару ручек, пару эндпоинтов — это не сложнее, чем написать сайт» — Эмиль.

Решение не в выборе стека, а в глубине. Расти в архитектуру, продуктовый контекст, ответственность за решения. AI как инструмент, не как угроза.

---

## Стратегия мягкого перехода (если есть текущая работа)

Резкий перекат с увольнением — необязателен. Альтернатива:

1. **Внутри текущего проекта** — попроси задачи на бэк, если бэк на Go
2. **Стань фулстеком** — пиши и фронт, и бэк параллельно, добивай Go в фоне
3. **Перетекай постепенно** — берёшь больше бэковых задач, меньше фронтовых
4. **Ищи чистую Go-позицию когда уверен** — у тебя уже есть полугода-год коммерческого Go

Этот путь медленнее, но менее стрессовый и почти без риска.

---

## Почему именно Go, а не Node.js / Java / Rust

- **Node.js** — логичный шаг для JS, но: однопоточность, callback hell, менее строгая типизация. Зарплаты ниже Go.
- **Java/Kotlin (Spring)** — порог входа высокий, экосистема массивная, год учить. Платят хорошо, но дольше.
- **Rust** — крутая производительность, кривая обучения вертикальная. Не для быстрого переката.
- **Go** — простой синтаксис, быстрая компиляция (секунды), отличный тулинг из коробки, востребован в Яндекс/Тинькофф/Озон/ВК. Оптимален для перекатчика с фронта.

---

## Минусы Go (честно)

- Простота поверхностная: «Go simplicity is mostly skin-deep. It often comes at the cost of expressiveness».
- `if err != nil` на каждом шагу — визуальный шум в больших проектах
- Нет дженериков долго не было (теперь есть, но экосистема ещё не перестроилась)
- Нет перегрузки функций, нет дефолтных параметров — Options-паттерн вместо них
- Нет тернарного оператора, нет `while` (вместо него `for` без условия)

Это нюансы, не блокеры. Привыкаешь за 2 недели.

## Чек-лист готовности к собесам Go-мидла

| # | Тема | Готов? |
|---|---|---|
| 1 | Горутины, каналы, sync.Mutex, sync.WaitGroup | ☐ |
| 2 | Указатели: когда передавать значение, когда указатель | ☐ |
| 3 | Интерфейсы, structural typing, embedding | ☐ |
| 4 | Обработка ошибок: `%w`, `errors.Is`, `errors.As` | ☐ |
| 5 | context.Context — пробрасываешь везде | ☐ |
| 6 | PostgreSQL: индексы, транзакции, EXPLAIN ANALYZE | ☐ |
| 7 | Kafka или RabbitMQ — базовая работа |  ☐ |
| 8 | Структура проекта `/cmd`, `/internal`, слои | ☐ |
| 9 | Dependency injection через конструктор | ☐ |
| 10 | Тесты: table-driven, моки через интерфейсы | ☐ |
| 11 | Docker, docker-compose | ☐ |
| 12 | Базовый K8s (deployment, service, configmap) | ☐ |

Все чекбоксы — готов идти на собесы. Половина — добивай слабые места.
