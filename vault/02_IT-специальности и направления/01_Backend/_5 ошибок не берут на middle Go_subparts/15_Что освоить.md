### Что освоить
- Implicit interface implementation
- Interface segregation — маленькие интерфейсы
- Consumer-defined interfaces
- Mocking через интерфейсы (mockery, gomock)
- Dependency Inversion на практике

## Бонус: дополнительные маркеры (из реальных собесов)

| Маркер | Признак мидла |
|---|---|
| Контекст | `context.Context` пробрасывается во ВСЕ функции с I/O. Не `context.Background()` |
| HTTP-клиент | Свой `http.Client` с таймаутами, не `http.Get()` напрямую |
| SQL | Параметризованные запросы (`$1`, `?`), не конкатенация строк |
| Транзакции | HTTP-вызовы вынесены за пределы транзакции (outbox pattern) |
| Логи | `slog` со структурированными полями, не `fmt.Println` |
| Валидация | `go-playground/validator` или ручная, не «доверяю входу» |
| Типы | Структуры вместо `map[string]any` где можно |

## Кейс из транскриптов

Парень 22 года, учил Go 8 месяцев. Знал теорию: слайсы, горутины, GC. Но на ревью получал «пока junior». 5 отказов подряд.

За 2 недели переписал пет-проект:
- Структура `/internal`, `/cmd`
- Ошибки с `%w`
- DI через конструктор
- Горутины через `errgroup`
- Интерфейсы

Следующий собес — оффер 230к, удалёнка. Не «стал умнее за 2 недели». Код стал выглядеть мидловым.

---

## Чек-лист «5 фиксов»

| # | Ошибка | Фикс | Ключ |
|---|---|---|---|
| 1 | Игнор ошибок | `fmt.Errorf` + `%w`, `errors.Is/As` | Каждая ошибка с контекстом |
| 2 | Всё в main.go | `/cmd`, `/internal`, слои | Handler → service → repository |
| 3 | Глобальные переменные | Конструктор, DI | `NewServer(deps...)` |
| 4 | Горутины без контроля | `errgroup`, `n := n`, `ctx` | Никаких висящих горутин |
| 5 | Нет интерфейсов | Маленькие, у потребителя | Тестируешь моками |

Прошёл по своему пет-проекту с этим чек-листом — на следующий собес идёшь увереннее в 2 раза.
