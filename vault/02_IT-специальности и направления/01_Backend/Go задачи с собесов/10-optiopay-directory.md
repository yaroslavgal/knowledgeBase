# Corporate Directory

## Метаданные
- **Источник:** https://github.com/evt/home-assignments/tree/main/optiopay
- **Компания:** Optiopay
- **Уровень:** Middle
- **Время на выполнение:** 8-12 часов
- **Ключевые навыки:** Деревья, алгоритмы, in-memory структуры
- **Инфраструктура:** Нет (in-memory)

## ТЗ

### Описание
Реализовать in-memory корпоративный справочник (иерархия сотрудников). Найти ближайшего общего менеджера (Lowest Common Ancestor) для двух сотрудников.

### Модель

**Bureaucr.at — иерархическая организация:**
- CEO (Claire) наверху
- Каждый сотрудник имеет список подчинённых
- Менеджер = сотрудник с ≥1 подчинённым
- Все сотрудники в итоге подчиняются CEO

**Структура:**
```
        Claire (CEO)
       /     |     \
     John   Mary   Bob
    /   \      \
 Alice  Tom   Steve
```

### Функциональные требования

**Интерфейс:**
```go
type Directory interface {
    // FindClosestCommonManager находит ближайшего общего менеджера
    // (farthest from CEO — т.е. нижнего в иерархии)
    FindClosestCommonManager(employee1, employee2 string) (string, error)
}
```

**Требования:**
1. In-memory структура данных
2. Manager ссылается на подчинённых (не наоборот)
3. Поддержка добавления сотрудников
4. Поиск ближайшего общего менеджера

**Примеры:**

| Employee1 | Employee2 | Closest Common Manager |
|-----------|-----------|------------------------|
| Alice | Tom | John |
| Alice | Steve | Claire |
| John | Bob | Claire |
| Mary | Steve | Mary |

### Нефункциональные требования

1. **Алгоритм:**
   - Эффективный поиск (не полный обход дерева при каждом запросе)
   - Оптимально: O(h) где h — высота дерева

2. **Валидация:**
   - Обработка несуществующих сотрудников
   - Обработка случая когда один сотрудник — менеджер другого

3. **Тесты:**
   - Unit tests с разными сценариями
   - Граничные случаи (CEO, листья)

### Ограничения
- In-memory (без БД)
- Предполагается валидная иерархия (все под CEO)
- Менеджер → сотрудники (однонаправленная связь)

## Подсказки для ментора

### Типичные ошибки учеников
1. **Ребёнок → родитель** — делают ссылку наверх, хотя требуется наоборот
2. **Полный обход** — каждый поиск = O(n) обход всего дерева
3. **Нет валидации** — паника на несуществующем сотруднике
4. **Память** — дублирование объектов сотрудников

### Ключевые паттерны

**Структура:**
```go
type Employee struct {
    Name     string
    Reports  []*Employee  // подчинённые
}

type Directory struct {
    ceo *Employee
    // опционально: map для O(1) поиска
    index map[string]*Employee
}
```

**Алгоритм LCA (без parent указателя):**
```go
func (d *Directory) FindClosestCommonManager(e1, e2 string) string {
    // Считаем сколько поддеревьев содержат e1 и e2
    var result string
    var find func(emp *Employee) int
    
    find = func(emp *Employee) int {
        count := 0
        if emp.Name == e1 || emp.Name == e2 {
            count++
        }
        
        for _, report := range emp.Reports {
            count += find(report)
        }
        
        // Если нашли обоих в этом поддереве — это LCA
        if count == 2 && result == "" {
            result = emp.Name
        }
        
        return count
    }
    
    find(d.ceo)
    return result
}
```

**Алгоритм с parent (если добавить):**
```go
// 1. Собрать путь от e1 до CEO
// 2. Собрать путь от e2 до CEO  
// 3. Найти последний общий элемент (с конца)
```

### Уровневые подсказки
- 🟢 **Направление:** Нужно рекурсивно обойти дерево и считать сколько искомых сотрудников в каждом поддереве
- 🟡 **Конкретика:** Если поддерево содержит обоих — текущий узел = LCA
- 🔴 **Фрагмент:** ```go
func countTargets(node *Employee, target1, target2 string) int {
    count := 0
    if node.Name == target1 || node.Name == target2 {
        count = 1
    }
    for _, child := range node.Reports {
        count += countTargets(child, target1, target2)
    }
    return count
}
```
