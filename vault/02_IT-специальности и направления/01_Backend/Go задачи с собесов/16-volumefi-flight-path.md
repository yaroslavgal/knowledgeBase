# Flight Path Tracker

## Метаданные
- **Источник:** https://github.com/evt/home-assignments/tree/main/volume.finance
- **Компания:** Volume.finance
- **Уровень:** Middle
- **Время на выполнение:** 8-12 часов
- **Ключевые навыки:** Алгоритмы, DAG, графы, микросервис
- **Инфраструктура:** Нет (stateless)

## ТЗ

### Описание
Создать микросервис для определения маршрута полёта человека по списку перелётов. Сервис принимает неупорядоченный список рейсов и возвращает начальный и конечный аэропорты маршрута.

### Функциональные требования

**Эндпоинт:**

| Метод | URL | Body | Response |
|-------|-----|------|----------|
| POST | `/calculate` | JSON flights | JSON path |

**Формат запроса:**
```json
{
    "flights": [
        ["IND", "EWR"],
        ["SFO", "ATL"],
        ["GSO", "IND"],
        ["ATL", "GSO"]
    ]
}
```

**Формат ответа:**
```json
{
    "path": ["SFO", "EWR"]
}
```

**Примеры:**

| Input | Output | Пояснение |
|-------|--------|-----------|
| `[["SFO", "EWR"]]` | `["SFO", "EWR"]` | Один перелёт |
| `[["ATL", "EWR"], ["SFO", "ATL"]]` | `["SFO", "EWR"]` | Два перелёта |
| `[["IND", "EWR"], ["SFO", "ATL"], ["GSO", "IND"], ["ATL", "GSO"]]` | `["SFO", "EWR"]` | Цепочка из 4 |

**Бизнес-логика:**
1. Каждый перелёт: `[source, destination]`
2. Перелёты не упорядочены
3. Нужно построить полный маршрут от первого аэропорта до последнего
4. Гарантируется: один непрерывный маршрут (без разветвлений)

### Сложные сценарии

**1. Несколько DAG в одном запросе:**
```json
{
    "flights": [
        ["IND", "EWR"], ["SFO", "ATL"], ["GSO", "IND"], ["ATL", "GSO"],
        ["A", "B"], ["B", "C"], ["C", "D"], ["D", "E"]
    ]
}
```
Response: `[["SFO", "EWR"], ["A", "E"]]`

**2. Несколько точек старта и финиша (Cartesian product):**
```json
{
    "flights": [
        ["DEN", "ATL"], ["SFO", "ATL"],
        ["ATL", "GSO"], ["GSO", "IND"],
        ["IND", "EWR"], ["IND", "GJT"]
    ]
}
```
Response: `[["SFO", "EWR"], ["DEN", "EWR"], ["SFO", "GJT"], ["DEN", "GJT"]]`

### Нефункциональные требования

1. **Алгоритм:** O(n) по времени, O(n) по памяти
2. **Масштабируемость:** 100k+ рейсов в одном запросе
3. **Валидация:** невалидный input → 400 Bad Request
4. **Документация:** примеры запросов в `example/requests.sh`

### Ограничения
- Все аэропорты — 3-буквенные коды (IATA)
- Маршрут всегда существует и непрерывен
- Могут быть циклы? (уточнить у заказчика)

## Подсказки для ментора

### Типичные ошибки учеников
1. **Сортировка** — пытаются отсортировать, но это O(n log n)
2. **DFS/BFS overkill** — строят граф и обходят, хотя можно проще
3. **Нет обработки множественных DAG** — падают на втором примере
4. **Cartesian product** — не реализуют сложный сценарий
5. **Память** — создают полную матрицу смежности

### Ключевые паттерны

**Алгоритм O(n):**
```go
// Идея: считаем in-degree и out-degree
func CalculatePath(flights [][]string) []string {
    sources := make(map[string]int)  // аэропорт → сколько раз source
    dests := make(map[string]int)    // аэропорт → сколько раз destination
    
    for _, f := range flights {
        sources[f[0]]++
        dests[f[1]]++
    }
    
    // Start: больше source чем destination
    // End: больше destination чем source
    var start, end string
    for airport := range sources {
        if sources[airport] > dests[airport] {
            start = airport
        }
    }
    for airport := range dests {
        if dests[airport] > sources[airport] {
            end = airport
        }
    }
    
    return []string{start, end}
}
```

**Для нескольких DAG:**
- Разбить на компоненты связности
- Применить алгоритм к каждой

- 🟢 **Направление:** Подсчитай для каждого аэропорта сколько раз он входит и выходит
- 🟡 **Конкретика:** Start — где out > in, End — где in > out
- 🔴 **Фрагмент:** ```go
for _, flight := range flights {
    from, to := flight[0], flight[1]
    outDegree[from]++
    inDegree[to]++
}
```
