## Чтение чужого кода — твоя суперсила

70% времени работы ты ЧИТАЕШЬ код. Не пишешь. 

Задачи редко «напиши с нуля». Чаще «вот модуль на 10к строк, найди баг» или «добавь фичу в этот сервис».

Как читать правильно:
1. Сначала структура папок — пакеты, слои, точки входа
2. Потом entry point (main.go, app.tsx) — что инициализируется при старте
3. Потом конкретный flow по задаче — как запрос проходит от хэндлера до БД
4. Дебаггер + breakpoints, а не печать `console.log` везде
5. Ctrl+Click для навигации, Find Usages для импактов
6. Просматривай чужие PR — даже если не понимаешь полностью, видишь стиль команды

Записывай в блокнот всё, что не понимаешь. Через неделю — половина уже понятна сама. Оставшаяся — конкретные вопросы команде.
