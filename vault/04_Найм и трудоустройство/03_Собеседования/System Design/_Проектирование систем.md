## Ключевые концепции

### Масштабирование

**Вертикальное** — добавить CPU/RAM серверу. Простое но имеет предел.

**Горизонтальное** — добавить больше серверов. Сложнее, но без предела.

**Балансировщик нагрузки** — распределяет запросы между серверами. Nginx, HAProxy, AWS ALB.

### Базы данных

**SQL (PostgreSQL, MySQL)** — ACID, сложные запросы, транзакции. Хорошо для финансов, инвентаря, чего угодно с отношениями.

**NoSQL (MongoDB, Cassandra, Redis)** — гибкая схема, горизонтальное масштабирование. Хорошо для document store, кэша, временных данных.

**Выбор:** Если сомневаешься — бери PostgreSQL. Он справляется с 90% задач.

### Кэширование

**Redis** — in-memory хранилище. Кэш сессий, часто читаемых данных, счётчики.

**CDN** — кэш статики ближе к пользователю. CloudFront, Cloudflare.

**Когда кэшировать:** Данные часто читаются, редко меняются, вычисление дорогое.

**Инвалидация кэша** — сложнейшая проблема. TTL, event-driven invalidation, write-through/write-behind.

### Очереди сообщений

**Зачем:** Декаплинг сервисов, async обработка, буферизация под нагрузкой.

**Kafka** — высокая пропускная способность, хранение событий, replay. Для event streaming.

**RabbitMQ** — простой task queue, routing, dead letter queues. Для задач.

### Consistency vs Availability (CAP теорема)

В распределённой системе при сетевом разделении выбираешь: consistency (все видят одни данные) или availability (система отвечает).

Большинство систем выбирает availability + eventual consistency.

## Типовые задачи и подходы

### URL Shortener
База: KV-хранилище (Redis + PostgreSQL). Генерация ключа: Base62 от инкрементального ID или random. Редирект: 301 (кэшируется) vs 302 (трекинг).

### Лента новостей
Fan-out on write vs fan-out on read. Кэш последних постов. Pagination через cursor (не OFFSET).

### Система уведомлений
Очередь (Kafka/RabbitMQ) для async. Retry с exponential backoff. Dead letter queue для неудачных уведомлений. Rate limiting.

### Чат
WebSocket для real-time. Хранение сообщений в Cassandra (append-only). Горизонтальное масштабирование через sticky sessions или pub/sub.
