### Цепочка B — Замыкание в for-цикле

```go
for i := 0; i < 5; i++ {
    wg.Add(1)
    go func() { defer wg.Done(); fmt.Println(i) }()
}
```

1. «Что выведет на Go до 1.22?» (5 5 5 5 5)
2. «Почему пятёрки? Что захватывает замыкание — значение или указатель?»
3. «В Go 1.22 вывод другой. Что поменялось?»
4. «Это data race или race condition? -race поймает?»
5. «Покажи 3 способа починить (без апгрейда Go).»
6. ⚡ «Аналог в обычной функции, без цикла — приведи пример.»
7. «Где в реальном коде ловил такой баг?»

### Цепочка C — Каналы и утечки

1. «Запись в закрытый канал? Чтение из закрытого?»
2. «Как отличить «канал закрыт» от «прилетело zero value»?» (`v, ok := <-ch`)
3. «Что такое nil-канал? Чтение/запись? Зачем нужен?» (выключить ветку select)
4. «Утечка горутины — приведи 5 строк где висит навсегда.»
5. ⚡ Trap-задача:
```go
func slow() string {
    ch := make(chan string)
    go func() { ch <- fetchSlow() }()
    select {
    case s := <-ch: return s
    case <-time.After(1*time.Second): return "timeout"
    }
}
```
   → утечка. Если timeout — горутина повисла на ch <-. Фикс: `make(chan string, 1)`.
6. «Как обнаружить утечку в проде?» (pprof goroutine, goleak)
7. «Кто должен закрывать канал? Что если producers несколько?»

### Цепочка D — Data race и lost update

1. ```go
   counter := 0
   for i := 0; i < 1000; i++ { go func() { counter++ }() }
   ```
   «Что выведет? Будет ли число одинаковым?»
2. «Разложи `counter++` на машинные операции.»
3. «Atomic vs Mutex — когда что?»
4. ⚡ «Два счётчика которые должны быть синхронны. Можно ли только atomic?» (НЕТ)
5. «Race condition без data race — пример?» (TOCTOU под mutex)
6. ⚡ «sync.Map не ловится на -race. Значит быстрее map+RWMutex?» (Нет, специфический паттерн)
7. «Как работает -race? Почему не в проде?» (5-10× CPU overhead)
