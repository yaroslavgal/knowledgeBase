# STAR-истории

## Как написать историю по STAR

### Пример: Сложная техническая задача

**Situation:** В продакшене начались случайные падения сервиса ночью. Мониторинг показывал memory leak но источник был непонятен. Это было мое первое столкновение с подобной проблемой на продакшен-нагрузке.

**Task:** Найти и исправить причину в течение двух дней — бизнес терял деньги из-за даунтайма.

**Action:** Добавил детальное профилирование памяти. Написал скрипт для отслеживания объектов в heap. Воспроизвёл проблему локально с synthetic load. Обнаружил что connection pool не освобождал соединения при timeout. Исправил конфигурацию пула и добавил явный cleanup.

**Result:** Memory leak устранён. Даунтайм снизился с 3 раз в неделю до нуля за следующий месяц. Добавил alerting на метрики памяти чтобы ловить подобное раньше.

---

### Пример: Конфликт с коллегой

**Situation:** Спорили с senior-разработчиком о выборе архитектуры для нового сервиса. Он настаивал на монолите, я видел аргументы для сервис-ориентированного подхода.

**Task:** Прийти к решению которое команда может поддерживать долгосрочно, не затягивая разработку.

**Action:** Предложил структурированное сравнение: написал документ с pros/cons каждого подхода конкретно для нашего случая — размер команды, планы по масштабированию, существующая инфраструктура. Попросил senior-разработчика дополнить документ его аргументами. Провели встречу с командой где каждый мог задать вопросы.

**Result:** Решили начать с модульного монолита с чёткими границами — компромисс который учёл оба взгляда. Senior оценил что его аргументы были услышаны. Через год это решение оказалось правильным — команда выросла недостаточно чтобы оправдать микросервисы.

## Частые ошибки в STAR

Нет конкретных действий — только «мы решили», «команда сделала». Говори что конкретно сделал ты.

Нет результата с цифрами. «Всё получилось хорошо» — слабо. «Сократили время деплоя с 45 минут до 8 минут» — сильно.

История без конфликта или сложности. «Всё прошло гладко» — не STAR-история. Должна быть реальная сложность.

Слишком длинная — больше 3–4 минут. STAR должна укладываться в 2–3 минуты.
