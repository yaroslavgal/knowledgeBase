## JavaScript Core

### 1. Closure: что и зачем `J`

Функция, которая «помнит» переменные внешней области даже после её завершения. Под капотом — ссылка на LexicalEnvironment. Используется везде: хуки React, обработчики событий, модульный паттерн, каррирование.

### 2. ⚡ Что выведет? `J`
```js
for (var i = 0; i < 3; i++) setTimeout(() => console.log(i), 100);
```
**Ответ:** `3 3 3`. `var` функционально-скоупная — одна переменная на цикл. К моменту коллбэков `i === 3`. Фикс — `let` (блочная область, своя `i` на итерацию) → `0 1 2`.

### 3. var/let/const `J`
- `var` — функция, hoisting=undefined, переприсваивание+повторное объявление
- `let` — блок, TDZ, переприсваивание
- `const` — блок, TDZ, нельзя переприсвоить (но мутировать объект можно)

Правило: по умолчанию `const`, нужно менять — `let`, `var` — никогда.

### 4. Hoisting `J`
JS поднимает объявления на этапе компиляции. `function declaration` поднимается целиком. `var` поднимается значением `undefined`. `let`/`const` — попадают в TDZ (доступ → ReferenceError).

### 5. this в JS — 5 правил `M`
1. `obj.fn()` → `this = obj`
2. `fn()` → `window` (или `undefined` в strict)
3. arrow → берёт `this` из внешней области при создании
4. `new Fn()` → новый объект
5. `call/apply/bind` → явная привязка

Ловушка: `const fn = obj.greet; fn()` теряет контекст. Решение: `bind`, arrow или `.call()`.

### 6. == vs === `J`
`===` — без приведения типов. **Всегда**. `==` приводит типы по сложным правилам: `0 == ""`, `null == undefined`, `"" == false` — все `true`. Подвох: `NaN === NaN === false`, проверка через `Number.isNaN()`.

### 7. ⚡ Event Loop порядок `M`
```js
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
```
**Ответ:** `1 4 3 2`. Сначала весь синхронный код → опустошается ВСЯ Microtask Queue (Promise) → ОДИН Macrotask (setTimeout) → опять microtasks.

### 8. ⚡ Microtask ordering — что выведет? `S`
```js
Promise.resolve()
  .then(() => { console.log(1); return Promise.resolve(2); })
  .then(console.log);

Promise.resolve()
  .then(() => console.log(3))
  .then(() => console.log(4))
  .then(() => console.log(5));
```
**Ответ:** `1 3 4 2 5`. `return Promise.resolve(2)` — это thenable, unwrapping создаёт **2 дополнительных microtask'а**, поэтому `2` появляется позже ожидаемого.

### 9. Spread vs Rest `J`
Один синтаксис `...`, разное использование. Spread — раскладывает (`[...arr]`). Rest — собирает (`function(...args)`). Spread — **shallow** копия, вложенные объекты по ссылке. Глубокая копия — `structuredClone(obj)`.

### 10. Map/Set/WeakMap/WeakSet `M`
- Map — ключ любой тип, сохраняет порядок
- Set — уникальные значения
- WeakMap — ключи только объекты, GC может собрать, не итерируется. Кейс: приватные данные, кэш с автоочисткой
- WeakSet — аналогично для Set

### 11. null vs undefined `J`
- `undefined` — JS ставит автоматически (необъявлено, нет аргумента, нет свойства)
- `null` — программист явно «здесь пусто»
- Подвох: `typeof null === "object"` (исторический баг)

### 12. Optional chaining + Nullish `J`
- `?.` — безопасный доступ, при null/undefined → undefined вместо TypeError
- `??` — правый операнд только если левый null/undefined
- `||` — правый при ЛЮБОМ falsy (`0`, `""`, `false`)

`0 ?? 42 → 0`, `0 || 42 → 42`.

### 13. Каррирование `M`
`const add = a => b => c => a + b + c; add(1)(2)(3) // 6`. Зачем: частичное применение, специализация общих функций, композиция.
