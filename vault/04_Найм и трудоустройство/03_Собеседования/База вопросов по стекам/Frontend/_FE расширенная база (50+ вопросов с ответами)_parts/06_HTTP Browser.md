## HTTP / Browser

### 47. CORS — как работает `M`
Same-Origin Policy блокирует cross-origin. CORS — сервер разрешает через заголовки. Preflight (OPTIONS) — для не-simple запросов (PUT, DELETE, кастомные заголовки). Сервер отвечает `Access-Control-Allow-*`.

### 48. fetch — главная ловушка `J`
`fetch` НЕ бросает ошибку на 4xx/5xx. Нужно проверять `res.ok` или `res.status` вручную.

### 49. WebSocket vs SSE vs Polling `M`
- WS — двустороннее, постоянное (чат, игры)
- SSE — сервер→клиент, авто-реконнект (уведомления, ленты)
- Polling — периодические запросы (просто, неэффективно)

### 50. JWT vs Sessions `M`
- JWT — токен на клиенте, stateless, легко масштабируется, сложно инвалидировать (нужен blacklist)
- Sessions — ID на клиенте, данные на сервере. Легко инвалидировать, нужен shared store

### 51. XSS vs CSRF `M`
- XSS — внедрение JS. Защита: textContent вместо innerHTML, React экранирует, CSP
- CSRF — запрос от имени юзера с чужого сайта. Защита: SameSite cookies, CSRF-токены, проверка Origin

### 52. localStorage / sessionStorage / cookies `J`

| | localStorage | sessionStorage | Cookies |
|---|---|---|---|
| Размер | 5-10 MB | 5-10 MB | 4 KB |
| Живёт | Вечно | До закрытия вкладки | Настраиваемое |
| На сервер | Нет | Нет | Да, каждый запрос |
