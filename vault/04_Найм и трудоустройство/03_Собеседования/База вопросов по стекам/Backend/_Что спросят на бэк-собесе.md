# Что спросят на бэк-собесе

## Топ вопросы которые повторяются везде

### Базы данных

«Что такое индекс и как работает?»
B-tree структура, ускоряет поиск по условию WHERE и JOIN. Минусы: замедляет запись, занимает место. Добавляешь на поля которые часто используешь в WHERE, ORDER BY, JOIN.

«Что такое транзакция? ACID?»
Atomicity (всё или ничего), Consistency (данные всегда в валидном состоянии), Isolation (транзакции не видят друг друга), Durability (после commit данные сохранены даже при сбое).

«Что такое N+1 проблема?»
Запрос который делает 1 запрос для списка + N запросов для каждого элемента. Решение: JOIN или eager loading.

«Разница SQL vs NoSQL?»
SQL: строгая схема, ACID, сложные запросы. NoSQL: гибкая схема, горизонтальное масштабирование, eventual consistency. Выбор зависит от задачи — не «NoSQL быстрее».

### HTTP и API

«Разница REST vs gRPC?»
REST: HTTP/JSON, универсальный, читаемый, overhead больше. gRPC: HTTP/2 + protobuf, быстрее, сильная типизация, нужна кодогенерация. gRPC для внутренних сервисов где нужна производительность.

«Что такое idempotent запрос?»
Один и тот же запрос выполненный несколько раз даёт тот же результат. GET, PUT, DELETE — idempotent. POST — нет. Важно для retry логики.

### Конкурентность

«Что такое race condition?»
Два потока/горутины читают и изменяют общее состояние одновременно, результат зависит от порядка выполнения. Решение: mutex, atomic операции, channels (Go).

«Что такое deadlock?»
Два процесса ждут друг друга — оба заблокированы навсегда. Примеры в коде.

### Архитектура

«Монолит vs микросервисы?»
Монолит проще на старте, легче дебажить, нет сетевых вызовов. Микросервисы: независимый деплой, масштабирование, разные команды. Не начинай с микросервисов без причины.

«Что такое SOLID?»
Single responsibility, Open/closed, Liskov substitution, Interface segregation, Dependency inversion. Уметь объяснить каждый с примером.
