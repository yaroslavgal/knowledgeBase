# План подготовки за 3 дня (экстренный)

Собес через 72 часа. Ты не готов. Без паники — выучить ВСЁ невозможно, но 80% вопросов покрываются 20% тем. План ниже — именно те 20%.

Базовый шаблон под Go-бэкенд. Принципы те же для других стеков — меняй темы.

---

## Принцип

Не читай. Говори вслух. Чтение ≠ ответ под давлением.

Каждую тему прогоняешь по схеме: прочитал → закрыл → объяснил вслух как другу → если запнулся, разобрал причину → повторил.

3 дня = 3 блока по ~6 часов чистого времени. Спи нормально, не сиди ночью — мозг на свежую голову работает лучше.

---

## ДЕНЬ 1 — Ядро языка

Без этого блока не пройти ни джуна, ни мидла.

### Утро (3 ч): Concurrency

- Горутина: ~2-8 KB стек, userspace переключение, M:N к OS-тредам
- GMP-модель: G/M/P, локальные очереди, work stealing
- Каналы: буф/небуф, что при чтении/записи в закрытый/nil канал
- `sync.Mutex`, `RWMutex`, `WaitGroup`, `Once`, `atomic`
- Data race vs Race condition — это РАЗНЫЕ вещи. `-race` ловит только первое

Решить руками:
```go
// Что выведет до Go 1.22?
for i := 0; i < 5; i++ {
    go func() { fmt.Println(i) }()
}
// Ответ: 5 5 5 5 5. Фикс: go func(v int){fmt.Println(v)}(i)
```

### День (2 ч): Слайсы и Мапы

- Slice = `{ptr, len, cap}`, append может реаллоцировать
- `make([]T, 0, N)` — преаллокация
- Trap с full slice expression `s[1:3:3]`
- Map: бакеты по 8, эвакуация при load factor 6.5, рандомный обход by design
- Конкурентный доступ к map → fatal. `sync.Map` или RWMutex

### Вечер (1 ч): Интерфейсы и указатели

- Pointer vs value receiver — кто реализует интерфейс
- Nil-интерфейс ловушка (type=*T, value=nil → interface != nil)
- Embedding — композиция, не наследование
- Compile-time check: `var _ Iface = (*Type)(nil)`

## ДЕНЬ 2 — БД + Инфра

### Утро (2 ч): PostgreSQL

- ACID — каждую букву с примером
- Уровни изоляции: RU/RC/RR/Serializable. PG default = RC
- Dirty read / Non-repeatable / Phantom — по сценарию
- Индексы: B-tree, составной (leftmost prefix), когда не работает (LIKE '%x%', функция от столбца, низкая кардинальность)
- `EXPLAIN ANALYZE` — уметь читать, отличать Seq Scan от Index Scan

### День (2 ч): Kafka + RabbitMQ

- Чем отличаются: лог vs очередь, pull vs push, replay
- Partition / Consumer Group / Offset
- Гарантии: at-most-once / at-least-once / exactly-once. В проде — at-least-once + idempotent consumer
- Дедуп по event_id (`INSERT ... ON CONFLICT DO NOTHING`)

### Вечер (2 ч): Docker + основы DevOps

- Dockerfile для Go-приложения (multi-stage build, обязательно)
- `docker-compose` поднять app + postgres + redis
- Чем контейнер отличается от ВМ
- Базовые `kubectl` команды (если позиция упоминает k8s)

```dockerfile
FROM golang:1.22-alpine AS build
WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 go build -o /bin/app ./cmd/app

FROM alpine:3.19
COPY --from=build /bin/app /bin/app
ENTRYPOINT ["/bin/app"]
```

## ДЕНЬ 3 — Лайвкод + прогон

### Утро (3 ч): Решить руками 5 задач

1. Worker pool из 3 воркеров через каналы
2. Merge каналов (fan-in) — закрытие выходного через WaitGroup
3. Потокобезопасный кэш (`sync.RWMutex + map`)
4. «Что выведет?» — defer с замыканием на named return
5. Простая алгоритмическая (two sum / reverse string с rune)

Каждую задачу — пишешь сам без подсказок, потом сравниваешь с эталоном.

Перед каждой решением **уточняешь требования вслух** даже у пустого экрана: «Входные могут быть пустыми? Какой ожидаемый результат? Ограничения по памяти?» — это привычка.

### День (2 ч): Сети + HTTP + soft

- HTTP/HTTPS, TCP/UDP, status codes (200/204/301/400/401/403/404/409/500/502/504)
- REST принципы (stateless, idempotent методы)
- gRPC vs REST — когда что
- JWT vs session — почему JWT нельзя revoke напрямую

### Вечер (1 ч): Полный mock с другом или ChatGPT

- 30 минут вопросы по схеме реального собеса
- Без шпаргалок
- Запиши на видео, потом пересмотри (увидишь паузы, мычание, неуверенные формулировки)

## Тактика на самом собесе

**Знаешь тему хорошо** → иди вглубь и вширь, рассказывай смежные темы. Сильный кандидат экспансивен.

**Не знаешь** → НЕ молчи. Структура ответа: «Что — Почему — Как — Когда».
> «Термин слышал, глубоко не копал. Судя по названию — это про X. Логика скорее всего такая... Правильно думаю?»

**Мычание = провал.** Лучше сказать «дай мне минуту подумать» и подумать.

**80% правильных ответов = успешный собес.** Не нужно отвечать на все 100%. Не надо паниковать что не ответил на 1-2 вопроса.

## Чего НЕ делать в эти 3 дня

- Учить алгоритмы хардкорно если ты идёшь не в FAANG. Пустая трата времени.
- Читать книги. На чтение нет времени, нужны мускулы памяти.
- Смотреть 2-часовые мок-собесы целиком. Смотри 5-минутные нарезки конкретных тем.
- Учить System Design если идёшь на джуна/мидла. Спросят 30% случаев, выучить за 3 дня нереально.
- Сидеть за полночь. Уставший мозг на собесе хуже подготовленного на 70%.

См. `_Четыре_типа_собесов.md` для тактики на каждом этапе.
