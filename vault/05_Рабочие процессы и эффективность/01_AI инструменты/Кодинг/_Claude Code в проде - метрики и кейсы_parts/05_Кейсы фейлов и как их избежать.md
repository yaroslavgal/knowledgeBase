## Кейсы фейлов и как их избежать

### Кейс 1: «После N итераций — сжирает токены»

> «Не важно как бы ни были круты агенты, после n итераций накопленные ошибки делают нейронную разработку невозможной и просто сжирают токены»

**Причина:** контекст забивается, ошибки накапливаются, Claude теряет фокус.

**Фикс:**
- Дроби фичу на 3–4 фазы
- После каждой фазы — `/clear` и загрузка плана из GitHub Issue
- `/context` — мониторь заполнение, чисти при >60%

### Кейс 2: «Дизайн от Claude — топорный»

> *«С нуля дизайн в Claude качественный не сделаешь»*

**Причина:** Claude слабый в визуальной эстетике без референсов.

**Фикс:** drag & drop скриншотов референса в CLI (работает с октября 2025). Не «сделай красиво», а «реализуй вот этот макет на React + Tailwind, используя нашу дизайн-систему из `src/design/tokens.ts`».

Ещё лучше: связка с другой нейронкой для генерации UI (v0, Stitch) → скриншот в Claude Code → реализация в коде.

### Кейс 3: «Создал файлы в неправильных папках»

Реальный комментарий: *«Клод создавал файлы в неправильных папках, путал наш custom middleware со стандартным, а тесты писал на моках, хотя у нас integration tests на testcontainers.»*

**Фикс:** CLAUDE.md с явным указанием:
- Где какие файлы лежат (`internal/handler/`, `internal/repository/`)
- Что у нас testcontainers, не моки
- Какой именно middleware использовать

Без CLAUDE.md — Claude угадывает по best practices, которые могут не совпасть с твоим проектом.

### Кейс 4: «Тысяча строк unmaintainable slop»

> *«Watching this after realising I have to totally rewrite the thousand lines of functional but completely unmaintainable slop components that Claude Code added to my project»*

**Причина:** Claude писал без плана, без архитектурных правил, без ревью каждой фазы.

**Фикс:** Plan Mode → ревью плана → только потом код. И **ревью каждого коммита** глазами, а не «accept all».
