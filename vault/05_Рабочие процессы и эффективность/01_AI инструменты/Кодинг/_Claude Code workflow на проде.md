# Claude Code на реальном проекте — инженерный workflow

Не «сделай мне todo за 15 минут», а как использовать на легаси с 10K+ строк, чтобы код проходил ревью.

## Главное правило

Без `Plan Mode`, `CLAUDE.md` и валидации Claude Code превращается в генератор мусора — после 5–10 итераций «накопленные ошибки делают разработку невозможной и сжирают токены».

---

## Этап 1: Plan Mode — всегда

Включить: `Shift+Tab` до режима plan.

Никогда не стартуй в edit mode на задаче сложнее бага. План-мод заставляет Claude:
- исследовать кодовую базу
- задать уточняющие вопросы (размер страницы, нужна ли фильтрация)
- показать план до написания кода

Плохо:
```
> Добавь эндпоинт /users с пагинацией
```
Claude дублирует структуры, путает middleware, пишет в неправильную папку.

Хорошо:
```
> [Plan Mode]
> Нужен GET /api/v1/users с cursor-based пагинацией.
> Изучи internal/handler/, используй паттерн как в /api/v1/orders.
> Покажи план перед кодом.
```

Не принимай план слепо — редактируй и тыкай носом в проблемы.

---

## Этап 2: CLAUDE.md — корпоративная память проекта

Без него Claude каждую сессию заново «знакомится» с проектом и галлюцинирует. Оптимальный размер — **~300 строк**. Больше = bloat, меньше точность.

Что класть (Go-пример):

```markdown
# Project: payment-service
## Architecture
- Go 1.22, chi router, sqlx (no ORM, raw SQL)
- Layered: handler → service → repository
- Handlers: internal/handler/, queries: internal/repository/

## Code Style
- Be extremely concise. Sacrifice grammar for concision.
- Table-driven tests
- Error wrapping: fmt.Errorf("operation: %w", err)

## Validation Loop (run after every change)
1. go build ./...
2. go vet ./...
3. go test ./... -count=1
4. golangci-lint run
```

Frontend-аналог:
```markdown
1. npx tsc --noEmit
2. npm run lint
3. npm run test -- --watchAll=false
```

Лайфхак: `/init` создаёт скелет, дальше доруливаешь руками.

## Этап 3: Мультифазная работа — против деменции контекста

После 60–70% заполнения контекста качество ответов падает. К концу дня Claude путает файлы и повторяет ошибки.

Воркфлоу больших фич:
1. План → мультифазный
2. Сохрани план **во внешнее хранилище** (GitHub Issue, markdown в репо)
3. Выполни фазу 1 → коммит
4. `/clear` (чистка контекста)
5. Загрузи план → фаза 2

`/context` — посмотреть, насколько забит контекст. Если >60% — пора чистить.

---

## Этап 4: Validation loop — Claude сам себя чинит

В CLAUDE.md прописываешь команды проверки. После каждого изменения Claude сам прогоняет тесты, линтер, сборку и итеративно фиксит до зелёного.

Без этого: «думает», что всё работает.
С этим: «AI just keeps going until it fixes itself» (Meta Staff Engineer).

---

## Этап 5: Subagents — параллелизм и изоляция

Каждый субагент — изолированный контекст. Используй для:
- параллельных задач (один пишет тесты, другой рефакторит, третий — доку)
- разовых исследовательских задач (не загрязняешь основной контекст)
- иерархии (тимлид-агент распределяет задачи)

Запуск через `Task tool`. Экономит токены — каждый видит только нужные файлы.

---

## Этап 6: Skills — переиспользуемые навыки

Skills загружаются **лениво** (progressive disclosure): только заголовок постоянно в контексте, тело — когда нужно. Дешевле MCP по токенам.

Полезные skills для Go-проекта:
- `go-review` — ревью по стайл-гайду компании
- `db-migration` — генерация миграций по паттерну
- `new-handler` — шаблон нового хендлера + тестов

Один раз нарисовал — работает между сессиями.

---

## Этап 7: Голосовой ввод промптов

Голосовые промпты длиннее, детальнее, содержат больше контекста. Печатая, ты режешь промпт; диктуя — добавляешь нюансы.

Тулзы: Whisper Flow, macOS dictation, Voice Input в VS Code.

---

## Чек-лист перед стартом задачи

- [ ] CLAUDE.md актуален
- [ ] План создан (Plan Mode)
- [ ] План разбит на фазы (если задача >2 часов)
- [ ] Validation loop работает (`go test` зелёный на main)
- [ ] Контекст чистый (<30% после `/clear`)

Без этого — теряешь 40% времени на правку AI-кода.

---

## Цифры из практики

- Подписка Max $100 окупается за **2 дня работы** при правильном workflow.
- Без CLAUDE.md и Plan Mode — лимиты кончаются за день, токены жгутся в пустоту.
- Mid-разработчик с настроенным Claude Code закрывает на **40% больше задач** в спринте.
