# System Design подготовка через Claude Code

Самая проваливаемая секция на сеньорных собесах. Можно подготовиться без ментора за 5К/час — Claude Code как спарринг-партнёр.

## Главная проблема SD-собеса

Навык работы ≠ навык собеса. На работе у тебя недели на проектирование. На собесе — **50–60 минут**. И уложить нужно всю архитектуру.

«Кто сможет за час спроектировать Twitter — ту систему, которую годами проектируют сотни инженеров?» — реальная боль.

Тренировать нужно именно «уложиться в 50 минут с аргументацией», а не теорию.

---

## Roadmap SD-интервью — 6 этапов с таймингами

| Этап | Время | Что делать |
|---|---|---|
| 1. Сбор требований | 10 мин | Функциональные + нефункциональные. Не больше! |
| 2. Оценка нагрузки | 5 мин | RPS, storage, bandwidth |
| 3. API Design | 5 мин | Эндпоинты, контракты |
| 4. **Архитектура + модель данных** | **25 мин** | Основной блок, не застревать на одном сервисе |
| 5. Отказоустойчивость | 5 мин | Что если упадёт X? |
| 6. Расчёт ресурсов | 5 мин | Шарды, реплики, кэш |

Без roadmap кандидаты тратят 25 минут на требования, потом 20 на один сервис → архитектура не показана → отказ.

## Workflow подготовки с Claude Code

**Шаг 1 — задача от AI как от интервьюера:**
```
> Ты — интервьюер в Яндексе на Senior Go.
> Дай задачу по System Design L5–L6.
> Веди по этапам, контролируй тайминг.
```
Получаешь задачу типа «спроектируй систему доставки уведомлений для 50M DAU».

**Шаг 2 — сбор требований вслух:**
```
> Функциональные: push/email/sms, приоритеты, retry.
> Нефункциональные: latency <1s push, at-least-once.
> Что упустил?
```
Claude задаёт каверзные вопросы: «А rate limiting? А геораспределённость?»

**Шаг 3 — нагрузка и архитектура:**
Claude ловит ошибки в арифметике, спрашивает «почему Kafka, а не RabbitMQ?», подкидывает edge cases.

**Шаг 4 — фидбэк в конце:**
- Сильные стороны
- Зоны роста (конкретно — где «поплыл»)
- Оценка уровня

---

## Топ-5 ошибок (на которые Claude давит)

1. **Нет самостоятельности** — ждёшь, что интервьюер поведёт. Должно быть наоборот: ты ведёшь его за ручку.
2. **Нет аргументации** — «возьму PostgreSQL» без «потому что». Скажи хотя бы «есть экспертиза».
3. **Уход в один компонент** — идеально проработал auth-service, а архитектуры нет. Лучше абстрактная архитектура целиком, чем детальный один сервис.
4. **Зазубривание готовых решений** — выучил «Design Twitter», просят «Twitter для фотографов» — паника.
5. **Игнор edge cases** — рассматриваешь только happy path. Реальный плюс: «А что будет, если автомобиль заедет в тоннель без связи?»

Claude специально задаёт «вопросы влево» — тренирует реакцию на неожиданное.

## База — 10 тем, покрывающих 80% SD-интервью

1. Кэширование (Redis, Memcached — когда что)
2. Балансировка нагрузки (L4/L7, алгоритмы)
3. SQL vs NoSQL (когда что выбирать)
4. Очереди (Kafka vs RabbitMQ)
5. Репликация и шардирование
6. API Design (REST, gRPC)
7. Микросервисы vs монолит
8. CAP-теорема и компромиссы
9. CDN и оптимизация чтения
10. Отказоустойчивость и мониторинг

Это и есть «20% знаний для 80% интервью». Гриндить дальше — упёрся в потолок.

## Как тренировать вербализацию

Главное отличие SD от LeetCode — нужно **проговаривать решения**. На LeetCode молча решил → получил зачёт. На SD молчишь → интервьюер не понимает, что ты думаешь → плохой фидбэк.

Claude Code в терминале как раз заставляет вербализовать — ты пишешь решения текстом → AI спрашивает «почему?» → учишься объяснять.

40 минут в день в течение 3–4 недель — нормальный режим для перехода с «знаю» к «могу донести за 50 минут».

## Промт-сетап для SD-сессии

```
Ты — Principal Engineer с 800+ проведёнными SD-интервью.
Проводишь со мной собес уровня L5 в FAANG-аналог.

Правила:
1. Дай задачу, потом веди меня по 6 этапам с таймингами
2. На каждом этапе задавай 2–3 уточняющих вопроса
3. Если ошибаюсь в арифметике — поправляй, но без подсказок
4. На архитектурных решениях спрашивай «почему?»
5. Подкидывай edge cases (отказ, рост нагрузки x10)
6. В конце — структурированный фидбэк: сильные/слабые/рекомендации/оценка уровня
```

Сохрани этот промт — каждая сессия начинается с него.

## Ограничения подхода

❌ Claude **не заменит** живого ментора с опытом FAANG-собесов — у него нет контекста конкретных компаний 2026 года.
❌ Не научит харизме и presence — это только живая практика.
❌ Не даст связи и рекомендации.

✅ Покрывает **80% тренировок**, которые раньше стоили 5–15К ₽ за сессию.
✅ Даёт безграничное количество подходов — пока не выработается мышечная память.
