# Mock-собес через Claude Code (vs голосовой через ChatGPT)

Голосовой мок через ChatGPT уже описан в [_Мок-интервью с AI - промты.md](_Мок-интервью%20с%20AI%20-%20промты.md). Здесь — другой формат: мок-собес в **терминале с Claude Code**, который сильнее в технических секциях.

## Когда что использовать

| Параметр | Голосовой ChatGPT | Claude Code в терминале |
|---|---|---|
| Поведенческие вопросы | ✅ Лучше | ➖ Слабее |
| Произношение английского | ✅ Лучше | ❌ Не та категория |
| Технические вопросы (теория) | ➖ Нормально | ✅ Лучше |
| Live coding с ловушками | ❌ Не катит | ✅ **Главный кейс** |
| Память между сессиями | ❌ Деменция | ✅ progress.md |
| Последовательная программа на N недель | ❌ Каждый раз с нуля | ✅ Запомнит слабые места |

Голос — для софт-скиллов и тренировки речи. Claude Code — для технической глубины и live coding.

---

## Главное отличие — давление и **fail-early**

Голосовой ChatGPT по умолчанию **слишком лояльный** — соглашается, не давит, подсказывает.

Claude Code в правильном промте давит:
- Не подсказывает ответ
- Задаёт follow-up на каждый ответ («а почему?», «а если нагрузка x10?»)
- Фиксирует пробелы и переходит дальше (не топчется)
- В конце — детальный фидбэк по каждой теме

---

## Системный промт для mock-режима

```
Ты — строгий интервьюер на позицию Middle Go-разработчика 
в продуктовой компании уровня Avito/Ozon.

Правила:
1. Задавай по одному вопросу за раз
2. НЕ давай ответы, только оценивай мои
3. Если ответ неполный — задавай уточняющие вопросы
4. Если я не знаю — зафиксируй пробел и переходи дальше
5. После технического вопроса — кодинг-задача с ловушкой
6. Имитируй давление: «время идёт», «короче, что выберешь?»
7. В конце — структурированный фидбэк с оценкой уровня

Начинай.
```

Сохрани в файл `mock_prompt.md` — каждая сессия с него.

## Что Claude задаёт по Go (типовой банк)

**Concurrency (тема №1):**
1. Горутина vs поток ОС — отличия
2. GMP-модель планировщика
3. Буферизованный vs небуферизованный канал
4. Что будет при записи в закрытый канал? Чтении?
5. Утечка горутины — как избежать
6. Задача: first-response-win для кластера реплик

**Подкапотные:**
7. Устройство слайса (header: pointer, len, cap)
8. Почему append возвращает слайс
9. Mаp: load factor, эвакуация
10. nil-интерфейс ловушка (тип vs значение)

**Кодинг-задачи с ловушками:**
- Worker pool с ограничением
- Fan-in/fan-out
- Таймаут через context
- Race condition на счётчике

## Формат фидбэка от Claude

После сессии:

```
## Сильные стороны
- Быстро понял задачу, не потребовались разъяснения
- Знаешь errors.Is vs ==
- Корректно использовал каналы

## Зоны роста
- Concurrency: забыл про утечку при небуферизованном канале (КРИТИЧНО)
- Не предложил декомпозицию функции > 40 строк
- Не уточнил требования перед реализацией

## Рекомендации
1. Повторить паттерны (fan-in, fan-out, pipeline)
2. Проходиться по примитивному кейсу перед «готово»
3. Тренировать вопрос «какие ограничения?» в начале

## Оценка уровня: Middle (уверенный)
```

За такой фидбэк живые менторы берут 3–5К ₽. Здесь — бесплатно/в рамках подписки.

---

## Типичные ошибки кандидатов (Claude их ловит)

1. Не уточняют требования перед кодом
2. Говорят «готово», не пройдя примитивный тест-кейс
3. Не знают `errors.Is` vs `==` (wrapped errors)
4. Копируют мьютексы (любой sync-объект **нельзя копировать**)
5. Не видят data race в очевидных местах (`len()` параллельно с `append`)
6. Путают concurrency и parallelism
7. Пишут функцию >50 строк без декомпозиции

Claude Code в роли интервьюера специально ставит ловушки на эти 7 пунктов.

## Многосессионная подготовка (то, чего не может голос)

Claude Code сохраняет в `mock_history.md`:
```
Сессия 1 (2026-04-01): Уровень — Middle минус.
Слабые: горутины, GC, контексты.

Сессия 5 (2026-04-12): Уровень — Middle.
Подтянул горутины. Слабое: SQL/индексы.

Сессия 12 (2026-05-01): Уровень — Middle+.
Готов к собесу.
```

В следующих сессиях Claude **знает твои слабые места** и фокусируется именно на них. Голосовой ChatGPT каждый раз начинает с нуля.

---

## Реалистичная программа подготовки

- 10–15 mock-сессий в Claude Code за 10–15 часов сфокусированной работы
- Длина сессии: 30–60 мин
- После каждой — разбор фидбэка, повтор слабых тем (не следующая сессия в тот же день!)
- Параллельно: 2–3 голосовых на ChatGPT для тренировки речи

Результат: на реальном собесе формат знаком, формулировки отшлифованы, 80% типовых ловушек уже встречал.

---

## Антипаттерны

❌ Просить «дай мне 30 вопросов и ответов» — это шпаргалка, не тренировка.
❌ Использовать AI как подсказчик во время mock — обнуляет смысл.
❌ Сразу после провала запускать вторую сессию — нужно разобрать фидбэк, иначе те же ошибки.
❌ Mock без последующего изучения слабых мест — крутишься на месте.
