## СЦЕНАРИЙ А: ПЕРЕКАТ ИЗ ДРУГОГО ЯЗЫКА (2–3 МЕСЯЦА)

### Неделя 1: Синтаксис и идиомы Go

| День | Тема | Действие |
|------|------|----------|
| 1 | Установка Go, `go run`, `go fmt`, `go vet`, `go mod init` | Hello World, разбор tooling |
| 2 | Tour of Go (go.dev/tour) — Basics | Все упражнения. Сравнить мысленно с Python/JS |
| 3 | Tour of Go — Methods, Interfaces | Понять "implicit interface implementation" |
| 4 | Tour of Go — Concurrency (goroutines, channels) | Аналогия: горутина = `asyncio.create_task`, канал = `queue.Queue` |
| 5 | Go by Example (gobyexample.com) — слайсы, мапы, структуры | Прописать каждый пример руками, не копи-пастить |
| 6 | Указатели — `*` и `&` | Аналогия: `&` = "дай адрес оригинала". Без указателя — копия |
| 7 | Обработка ошибок — `if err != nil`, `fmt.Errorf("...: %w", err)` | Никаких `_`. Каждую ошибку оборачивать |

### Неделя 2: Стандартная библиотека и первый сервер

| День | Тема | Действие |
|------|------|----------|
| 8 | `encoding/json` — Marshal/Unmarshal, struct tags | Парсинг JSON, обратное преобразование |
| 9 | `net/http` — Server, ServeMux, Handler/HandlerFunc | Простой HTTP-сервер из 30 строк |
| 10 | Middleware — функции-обёртки `func(http.Handler) http.Handler` | Логирование запросов, восстановление от паники |
| 11 | `context.Context` — таймауты, отмена, передача через цепочку вызовов | Каждый handler принимает `ctx`. Ни одного `context.Background()` внутри запроса |
| 12 | Тестирование — `testing` пакет, table-driven tests, `httptest` | Покрытие хэндлеров тестами |
| 13 | `database/sql` — подключение к PostgreSQL | Поднимаешь postgres в Docker, подключаешься |
| 14 | Запросы с параметрами, `QueryContext`, `defer rows.Close()` | Никаких склеек строк. Параметризованные запросы |

### Неделя 3: Конкурентность и реальный проект

| День | Тема | Действие |

| 15 | Горутины и каналы на практике | Параллельные HTTP-запросы через `errgroup` |
| 16 | `sync.Mutex`, `sync.RWMutex`, `sync.Map`, `sync.Once` | Когда что использовать. Race condition vs deadlock |

### Неделя 4: Pet-проект "URL-shortener" с микросервисной структурой

Цель — собрать сервис, который не стыдно показать на собесе.

**Стек:**
- HTTP-сервер на `net/http` + `chi` (минималистичный роутер)
- PostgreSQL для хранения URL
- Redis для кэширования
- Docker Compose для запуска
- Юнит-тесты для service-слоя
- Интеграционные тесты с `testcontainers-go`
- Graceful shutdown через `signal.NotifyContext`
- README с инструкцией запуска
- Dockerfile с multi-stage build

**Дни 22–28** — пилишь проект каждый вечер. К концу недели — готовый сервис на GitHub.

### Месяц 2: Углубление + второй проект + начало собесов

**Неделя 5–6:** gRPC, protobuf. Второй проект — микросервис уведомлений с gRPC API + Kafka producer/consumer.

**Неделя 7:** Kafka на практике — поднял локально, написал producer и consumer на Go. Понять partition, offset, consumer groups.

**Неделя 8:** Подготовка к собесам:
- Решение типовых задач (worker pool, rate limiter, LRU cache, pipeline)
- Повторение горутин и каналов до автоматизма
- System Design базовый (URL shortener, чат, нотификации)
- 5–10 мок-собесов (с друзьями, ChatGPT/Claude, через Telegram-чаты)

### Месяц 3: Реальные собесы

- Резюме под Go-вакансии (см. файл "_Резюме под ATS и AI-скрининг.md")
- 5–10 откликов в день в HH + Telegram-каналы
- На каждом собесе — записывать вопросы, разбирать слабые места после
- К концу месяца 3: оффер 100–160К (junior) или 180–250К (если убедил, что middle)
