## Часть 5: Подготовка к Go-Собесам

### 5.1 Топ-9 Тем (80% Всех Go-Собесов)

**1. Горутины и конкурентность (спрашивают ВСЕГДА)**
- Горутина ≠ поток ОС. Лёгкая корутина, стек 2-8 КБ, переключение в userspace
- GMP-модель: Goroutine → Machine thread → Processor. Локальные и глобальные очереди. Work stealing
- Каналы: буферизированные vs небуферизированные
- Nil-канал: read = block forever, write = block forever (используется для отключения ветки select)
- Data Race vs Race Condition — РАЗНЫЕ вещи. Data race = `go run -race`. Race condition = только мозг
- Классика: захват переменной цикла в горутине (до Go 1.22 все печатают одно значение)
- После Go 1.22: переменная цикла уникальна на каждую итерацию. На собесах всё ещё спрашивают

**2. Слайсы и Мапы**
- Slice = указатель на массив + length + capacity
- Append может создать НОВЫЙ массив (при превышении capacity). Старый слайс указывает на старый
- Передача слайса в функцию = копия заголовка. Append внутри функции → caller не видит
- Map = хэш-таблица, бакеты по 8 элементов, случайный порядок обхода BY DESIGN
- Конкурентная запись в map без мьютекса = runtime PANIC (не data race, а паника)
- Ключ: любой comparable тип

**3. Интерфейсы и Указатели**
- Всё в Go передаётся по значению (копируется)
- Pointer receiver (*T) vs value receiver (T)
- Интерфейсы: duck typing (имплицитная), empty interface{} / any (с 1.18)
- Embedding = композиция, НЕ наследование
- Ловушка: `p = &Person{...}` внутри функции = меняет локальную копию указателя

**4. Обработка ошибок (30-40% кода в Go)**
- `if err != nil` вместо try/catch
- `fmt.Errorf("context: %w", err)` для wrapping (не errors.New!)
- Sentinel errors vs custom error types
- errors.Is() и errors.As() для проверки цепочки

**5. PostgreSQL + ACID**
- ACID: Atomicity, Consistency, Isolation, Durability
- Уровни изоляции: Read Uncommitted → Read Committed (Postgres default) → Repeatable Read → Serializable
- B-tree индексы, составные индексы, EXPLAIN

**6. Kafka vs RabbitMQ**
- Kafka = распределённый ЛОГ (сообщения НЕ удаляются). RabbitMQ = очередь (удаляются)
- Consumer, Producer, Topic, Partition, Offset, Consumer Group
- Гарантии: at-most-once, at-least-once, exactly-once

**7. Docker**
- Multi-stage build: компиляция в golang:alpine, запуск в alpine:latest → образ с 1GB до ~15MB
- docker-compose: app + postgres + redis

**8. System Design**
- 6 этапов: требования (10 мин) → оценка нагрузки (5) → API (5) → data model (5) → архитектура (15) → feedback (5)
- 10 тем покрывают 80% SD-собесов
- 16 типичных ошибок. Топ-5: прыгать в дизайн без требований, не считать capacity, игнорировать нефункциональные требования, усложнять начальный дизайн, не обсуждать trade-offs

**9. Сети и Протоколы**
- HTTP vs HTTPS, TCP vs UDP
- REST API, gRPC (чем отличается от REST)
- "Что происходит когда вводишь URL" — спрашивают Avito, Astral, 2GIS
